# 11. Пользовательские истории (User Stories)

Юзер-стори (`US`) — это **единица бэклога** для команды: небольшая, независимая, проверяемая (критерии INVEST). В отличие от UR ([раздел 06](06-user-requirements.md)), которые описывают возможности продукта, истории режут эти возможности на куски, которые делаются за спринт. Каждая история содержит критерии приёмки в формате Gherkin (Дано / Когда / Тогда), которые QA переносит в тест-кейсы.

## 11.1. Карта историй

## 11.2. Definition of Ready и Definition of Done

**Историю берут в спринт (DoR), если:** у неё есть формулировка «Как… хочу… чтобы…», критерии приёмки, связи с FR и EC, известен контракт API, нет блокирующих зависимостей.

**История готова (DoD), если:** все критерии приёмки проходят автотестами, код прошёл ревью, контракт API соответствует `api/openapi.yaml`, связанные краевые кейсы покрыты тестами, документация обновлена.

## E-01. Расписание

### US-01. Расписание на день

**Как** клиент, **я хочу** видеть занятия выбранного дня со свободными местами, **чтобы** выбрать подходящее.
Связи: UR-01, UR-02, UR-12 · FR-04, FR-05 · `GET /v1/schedule` · Must

```gherkin
# language: ru
Функция: Расписание на день

  Сценарий: Просмотр расписания на сегодня
    Дано на сегодня опубликовано групповое занятие "Йога" в 19:00 с вместимостью 25 и 18 записями
    Когда клиент открывает расписание
    Тогда он видит "Йога" в 19:00 с отметкой "Осталось 7 из 25"

  Сценарий: Уже начавшиеся и отменённые сеансы не показываются
    Дано сейчас 19:10, сеанс "Йога" начался в 19:00, а сеанс "Зумба" в 20:00 отменён клубом
    Когда клиент открывает расписание на сегодня
    Тогда в списке нет ни "Йоги" в 19:00, ни "Зумбы" в 20:00

  Сценарий: Дата вне горизонта записи
    Когда клиент запрашивает расписание на дату через 14 дней от сегодня
    Тогда система возвращает ошибку OUT_OF_HORIZON
```

### US-02. Фильтры расписания

**Как** клиент, **я хочу** фильтровать расписание по типу, виду, тренеру и уровню, **чтобы** быстро найти своё занятие.
Связи: UR-03 · FR-07 · `GET /v1/schedule?type=&activity_type_id=&trainer_id=&level=` · Should

```gherkin
# language: ru
Функция: Фильтры расписания

  Сценарий: Комбинация фильтров
    Дано на дату есть "Йога" у Иванова, "Йога" у Петровой и "Сайклинг" у Иванова
    Когда клиент выбирает вид "Йога" и тренера "Иванов"
    Тогда он видит только "Йогу" у Иванова

  Сценарий: Сброс фильтров
    Дано клиент применил фильтры
    Когда он нажимает "Сбросить"
    Тогда он видит полное расписание выбранного дня
```

### US-03. Скрытие недоступных персональных слотов

**Как** клиент, **я хочу** видеть только те персональные слоты, которые реально можно забронировать, **чтобы** не получать отказы.
Связи: UR-02, UR-06 · FR-06, FR-13 · EC-08, EC-12, EC-13 · Must

```gherkin
# language: ru
Функция: Доступность персональных слотов

  Сценарий: Забронированный слот и пересекающийся с ним скрываются
    Дано у тренера Сидорова слоты 18:00–19:00 и 18:30–19:30
    И другой клиент забронировал слот 18:00–19:00
    Когда клиент открывает персональные тренировки Сидорова
    Тогда он не видит ни слот 18:00–19:00, ни слот 18:30–19:30

  Сценарий: Слот менее чем за 24 часа не показывается
    Дано слот начинается через 23 часа
    Когда клиент открывает расписание
    Тогда слот не отображается

  Сценарий: Свой забронированный слот виден
    Дано клиент забронировал слот 18:00–19:00
    Когда он открывает расписание этого дня
    Тогда он видит слот с отметкой "Вы записаны"
```

### US-04. Карточка занятия

**Как** клиент, **я хочу** открыть подробности занятия, **чтобы** понимать, на что записываюсь.
Связи: UR-04 · FR-08 · `GET /v1/sessions/{sessionId}` · Must

```gherkin
# language: ru
Функция: Карточка занятия

  Сценарий: Карточка группового занятия
    Когда клиент открывает карточку "Йоги" в 19:00
    Тогда он видит описание, уровень, тренера, зал, время 19:00–20:00 и число свободных мест

  Сценарий: Карточка персонального слота
    Когда клиент открывает карточку персонального слота
    Тогда он видит пометку "Стоимость и оплата — по договорённости с тренером"
```

## E-02. Запись

### US-05. Запись на групповое занятие

**Как** клиент, **я хочу** записаться на групповое занятие одной кнопкой, **чтобы** не звонить на ресепшн.
Связи: UR-05 · FR-09, FR-10, FR-15 · UC-03 · `POST /v1/bookings` · Must

```gherkin
# language: ru
Функция: Запись на групповое занятие

  Сценарий: Успешная запись
    Дано на "Йоге" в 19:00 свободно 7 мест из 25
    Когда клиент нажимает "Записаться"
    Тогда создаётся запись со статусом "Активна"
    И свободных мест становится 6
    И клиент видит "Вы записаны. Отменить можно до 18:30"
    И в ленте появляется уведомление "Запись подтверждена"
```

### US-06. Отказ, когда мест нет

**Как** клиент, **я хочу** получать честный отказ, если места закончились, **чтобы** не прийти на переполненное занятие.
Связи: UR-07 · FR-10 · EC-01, EC-05 · Must

```gherkin
# language: ru
Функция: Контроль вместимости

  Сценарий: Мест нет
    Дано на занятии заняты все 25 мест
    Когда клиент пытается записаться
    Тогда он получает отказ "Мест нет"

  Сценарий: Гонка за последнее место
    Дано на занятии осталось 1 место
    Когда два клиента одновременно нажимают "Записаться"
    Тогда записан ровно один клиент
    И второй получает отказ "Мест нет"
    И занятых мест ровно 25

  Сценарий: Нагрузочная проверка
    Дано на занятии 25 свободных мест
    Когда поступает 500 одновременных запросов на запись от разных клиентов
    Тогда создаётся ровно 25 активных записей
```

### US-07. Защита от двойной записи

**Как** клиент, **я хочу**, чтобы случайное двойное нажатие не создавало две записи, **чтобы** не занимать чужое место.
Связи: FR-11, FR-14 · EC-02, EC-03 · Must

```gherkin
# language: ru
Функция: Идемпотентность записи

  Сценарий: Повтор запроса с тем же ключом
    Когда приложение дважды отправляет запрос на запись с одним и тем же ключом идемпотентности
    Тогда создаётся одна запись
    И оба ответа содержат одинаковый идентификатор записи

  Сценарий: Повторная запись с другого устройства
    Дано клиент уже записан на "Йогу" в 19:00
    Когда он пытается записаться на неё с другого устройства
    Тогда он получает сообщение "Вы уже записаны на это занятие"
```

### US-08. Запрет пересечений

**Как** клиент, **я хочу**, чтобы система не давала записаться на два занятия в одно время, **чтобы** не держать чужое место.
Связи: UR-07 · FR-12 · EC-10, EC-11 · Must

```gherkin
# language: ru
Функция: Пересечения по времени

  Структура сценария: Проверка пересечения с существующей записью
    Дано у клиента есть запись на занятие 19:00–20:00
    Когда он записывается на занятие <интервал>
    Тогда результат <результат>

    Примеры:
      | интервал    | результат                  |
      | 20:00–21:00 | запись создана             |
      | 18:00–19:00 | запись создана             |
      | 19:30–20:30 | отказ CLIENT_TIME_CONFLICT |
      | 18:30–19:15 | отказ CLIENT_TIME_CONFLICT |
```

### US-09. Бронь персонального слота

**Как** клиент, **я хочу** забронировать время у выбранного тренера, **чтобы** зафиксировать тренировку, а детали обсудить с тренером напрямую.
Связи: UR-06 · FR-09, FR-13 · UC-04 · EC-12, EC-13 · Must

```gherkin
# language: ru
Функция: Бронь персонального слота

  Сценарий: Успешная бронь
    Дано у тренера Сидорова свободен слот через 3 дня в 18:00–19:00
    Когда клиент бронирует слот
    Тогда создаётся запись со статусом "Активна"
    И слот больше не виден другим клиентам

  Сценарий: Тренер занят групповым занятием
    Дано у Сидорова в 18:30 групповое занятие, а слот 18:00–19:00 загружен по ошибке
    Когда клиент пытается забронировать этот слот
    Тогда он получает отказ "Тренер в это время занят"
```

### US-10. Закрытое окно записи

**Как** клиент, **я хочу** понимать, когда запись уже закрыта, **чтобы** не тратить время.
Связи: UR-07 · FR-09 (шаги 3–4) · EC-06, EC-07, EC-08 · Must

```gherkin
# language: ru
Функция: Окно записи

  Сценарий: Групповое занятие уже началось
    Дано сейчас 19:01, занятие началось в 19:00
    Когда клиент пытается записаться
    Тогда он получает отказ BOOKING_CLOSED

  Сценарий: Персональная тренировка менее чем за 24 часа
    Дано до начала слота 23 часа 59 минут
    Когда клиент пытается забронировать слот через API
    Тогда он получает отказ BOOKING_CLOSED
```

## E-03. Отмена

### US-11. Отмена до дедлайна

**Как** клиент, **я хочу** отменить запись в приложении, **чтобы** освободить место без звонка.
Связи: UR-09, UR-10 · FR-16…FR-18, FR-20, FR-21 · UC-06 · EC-14, EC-19, EC-21 · `POST /v1/bookings/{bookingId}/cancel` · Must

```gherkin
# language: ru
Функция: Отмена записи

  Сценарий: Отмена группового ровно на границе дедлайна
    Дано клиент записан на "Йогу" в 19:00
    И сейчас 18:30:00
    Когда клиент отменяет запись
    Тогда запись получает статус "Отменена клиентом"
    И свободных мест становится на 1 больше
    И напоминание по записи не приходит

  Сценарий: Отмена после замены тренера
    Дано на "Йоге" в 19:00 заменён тренер, сейчас 18:55
    Когда клиент отменяет запись
    Тогда отмена проходит успешно

  Сценарий: Повторная запись после отмены
    Дано клиент отменил запись на "Йогу" в 19:00, места есть
    Когда он снова записывается
    Тогда создаётся новая запись, а старая остаётся в истории
```

### US-12. Недопустимая отмена

**Как** клуб, **я хочу**, чтобы отмена после дедлайна и чужих записей была невозможна, **чтобы** правила соблюдались одинаково для всех.
Связи: FR-03, FR-16, FR-19 · EC-15…EC-18 · Must

```gherkin
# language: ru
Функция: Ограничения отмены

  Структура сценария: Отказ в отмене
    Дано <условие>
    Когда клиент пытается отменить запись
    Тогда он получает <ответ>

    Примеры:
      | условие                                               | ответ                        |
      | групповое в 19:00, сейчас 18:30:01                    | CANCELLATION_DEADLINE_PASSED |
      | персональное завтра в 10:00, сейчас 10:01 сегодня     | CANCELLATION_DEADLINE_PASSED |
      | запись завершена                                      | BOOKING_NOT_ACTIVE           |
      | запись принадлежит другому клиенту                    | 404                          |

  Сценарий: Повторная отмена
    Дано запись уже отменена клиентом
    Когда клиент снова отправляет отмену
    Тогда возвращается текущее состояние записи, число мест не меняется
```

## E-04. Мои записи и уведомления

### US-13. Мои записи

**Как** клиент, **я хочу** видеть свои предстоящие записи и историю, **чтобы** контролировать планы.
Связи: UR-08 · FR-03 · UC-05 · `GET /v1/me/bookings` · Must

# language: ru

  Сценарий: Предстоящие и история

    Когда он открывает "Мои записи"
    Тогда во вкладке "Предстоящие" есть завтрашняя запись со сроком отмены
    И во вкладке "История" есть завершённая запись

  Сценарий: Только свои записи
    Когда клиент открывает "Мои записи"
    Тогда он не видит записи других клиентов
```

### US-14. Уведомления и лента

**Как** клиент, **я хочу** получать push и видеть уведомления в ленте, **чтобы** ничего не пропустить, даже если push выключен.
Связи: UR-11 · FR-27…FR-29 · UC-07 · EC-28 · `GET /v1/me/notifications`, `POST /v1/me/devices` · Must

# language: ru

  Сценарий: Уведомление при недоставленном push

    Когда он записывается на занятие

    И в ленте появляется уведомление "Запись подтверждена" со счётчиком непрочитанных

  Сценарий: Отметка о прочтении
    Дано у клиента 2 непрочитанных уведомления
    Когда он открывает одно из них
    Тогда счётчик непрочитанных становится 1
```

### US-15. Напоминание

## E-05. Изменения со стороны клуба

### US-16. Отмена сеанса клубом

**Как** управляющий, **я хочу**, чтобы при отмене занятия все записавшиеся автоматически получали уведомление, **чтобы** ресепшн не обзванивал клиентов.
Связи: UR-14 · FR-22 · UC-08 · EC-20, EC-23 · `POST /internal/v1/sessions/{sessionId}/cancel` · Must

```gherkin
# language: ru
Функция: Отмена сеанса клубом

  Сценарий: Отмена группового занятия
    Дано на "Зумбе" 12 активных записей и 3 записи, отменённые клиентами
    Когда тех. специалист отменяет сеанс
    Тогда 12 записей получают статус "Отменена клубом"
    И 3 записи сохраняют статус "Отменена клиентом"
    И 12 клиентов получают уведомление "Занятие отменено клубом"
    И сеанс пропадает из расписания

  Сценарий: Тренер заболел — персональная тренировка отменяется
    Дано у клиента забронирован слот у тренера Сидорова
    Когда тех. специалист отменяет этот слот
    Тогда запись получает статус "Отменена клубом" и клиент получает уведомление
```

### US-17. Замена тренера группового занятия

**Как** клиент, **я хочу** узнать о замене тренера и иметь возможность отменить запись без ограничений, **чтобы** не идти к тренеру, которого не выбирал.
Связи: UR-10, UR-14 · FR-17, FR-23 · UC-09 · EC-21, EC-22 · `POST /internal/v1/sessions/{sessionId}/trainer` · Should

```gherkin
# language: ru
Функция: Замена тренера

  Сценарий: Замена на групповом занятии
    Дано на "Йоге" с Ивановым 10 активных записей
    Когда тех. специалист заменяет тренера на Петрову
    Тогда записи остаются активными
    И клиенты получают уведомление "Тренер заменён на Петрову. Вы можете отменить запись до начала занятия"

  Сценарий: Замена на персональной тренировке запрещена
    Когда тех. специалист пытается заменить тренера персонального слота
    Тогда операция отклоняется с предложением отменить слот

  Сценарий: Новый тренер занят
    Дано у Петровой в это время другое занятие
    Когда тех. специалист назначает её на "Йогу"
    Тогда операция отклоняется
```

### US-18. Защита от некорректных операций

**Как** тех. специалист, **я хочу**, чтобы система не давала мне сломать существующие записи, **чтобы** ошибки загрузки не били по клиентам.
Связи: UR-13 · FR-24 · EC-24 · Must

```gherkin
# language: ru
Функция: Ограничения технических операций

  Сценарий: Уменьшение вместимости ниже числа записей
    Дано на занятии 20 активных записей
    Когда тех. специалист меняет вместимость на 15
    Тогда операция отклоняется

  Сценарий: Перенос времени занятия с записями
    Дано на занятии есть активные записи
    Когда тех. специалист меняет время начала
    Тогда операция отклоняется, перенос выполняется через отмену и новый сеанс
```

## E-06. Правила и учёт

### US-19. Автоматическое завершение записей

**Как** управляющий, **я хочу**, чтобы прошедшие записи автоматически получали статус «Завершена», **чтобы** считать заполняемость занятий.
Связи: FR-25 · UC-10 · Should

```gherkin
# language: ru
Функция: Завершение записей

  Сценарий: Завершение после окончания занятия
    Дано занятие закончилось в 20:00, на нём 18 активных записей
    Когда наступает 20:15
    Тогда все 18 записей имеют статус "Завершена" с инициатором SYSTEM
```

### US-20. Настраиваемые правила

**Как** управляющий, **я хочу** менять сроки записи, отмены и напоминаний без выпуска новой версии, **чтобы** быстро подстраивать правила клуба.
Связи: UR-15 · FR-30 · Should

```gherkin
# language: ru
Функция: Настройки правил

  Сценарий: Изменение дедлайна отмены группового занятия
    Дано дедлайн отмены группового занятия 30 минут
    Когда параметр меняют на 60 минут
    Тогда через минуту отмена "Йоги" в 19:00 в 18:15 отклоняется
    И отмена в 17:55 проходит
```

### US-21. История статусов и выгрузки

**Как** управляющий, **я хочу** иметь полную историю статусов записей и отказов, **чтобы** считать метрики BG-01…BG-04 и разбирать спорные случаи.
Связи: UR-16 · FR-31, FR-32 · Must

```gherkin
# language: ru
Функция: История и выгрузки

  Сценарий: История записи
    Дано клиент записался, затем тренер был заменён, затем клиент отменил запись
    Когда запрашивается история записи
    Тогда она содержит статусы ACTIVE → CANCELLED_BY_CLIENT с временем и инициатором каждого изменения

  Сценарий: Отказы по причинам
    Когда строится выгрузка отказов за месяц
    Тогда по каждой причине (SESSION_FULL, CLIENT_TIME_CONFLICT и т. д.) указано число отказов
```
