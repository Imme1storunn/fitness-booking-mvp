# 12. Архитектура (C4)

Модель C4 описывает архитектуру на нескольких уровнях детализации. Здесь приведены два уровня: **контекст** (система и её окружение) и **контейнеры** (из чего система состоит). Уровни компонентов и кода в MVP не детализируются: правила записи описаны в функциональных требованиях ([раздел 07](07-functional-requirements.md)) и диаграмме состояний ([раздел 14](14-booking-state-diagram.md)).


## 12.1. Уровень 1. Контекст системы

![C4: контекст системы](/c4-context.png)

| Элемент | Тип | Ответственность | Связь с требованиями |
|---|---|---|---|
| Клиент | Человек | Смотрит расписание, записывается, отменяет, получает уведомления | UR-01…UR-12 |
| Тех. специалист | Человек | Загружает мастер-данные, выполняет операции клуба (отмена сеанса, замена тренера) | UR-13, UR-14, C-01 |
| Управляющий | Человек | Задаёт правила, получает выгрузки для метрик | UR-15, UR-16 |
| Система онлайн-записи | Наша система | Расписание, правила записи и отмены, уведомления | BR-01…BR-18 |
| Сервис аутентификации | Внешняя система | Выдаёт токены клиенту, подтверждает их и передаёт `user_id` | C-02, DEP-01 |
| APNs / FCM | Внешняя система | Доставляет push на iOS и Android | DEP-02 |

## 12.2. Уровень 2. Контейнеры

![C4: контейнеры](/c4-containers.png)

| Контейнер | Технология | Ответственность | Почему так |
|---|---|---|---|
| Мобильное приложение | iOS / Android | Экраны S-01…S-06, хранение токена, приём push | Канал клиента по C-07 |
| Booking API | REST, stateless | Публичный API для приложения (`/v1`) и служебный API для операций клуба (`/internal/v1`). Все правила записи и отмены выполняются здесь | Без состояния — масштабируется горизонтально (NFR-22) |
| Worker | Фоновые задачи | Отправляет push из очереди уведомлений, отправляет напоминания в срок, переводит прошедшие записи в «Завершена» | Отделяет медленные и внешние вызовы от запросов клиента (NFR-02, NFR-07) |
| База данных | PostgreSQL | Хранит все данные. Гарантирует атомарность и ограничения целостности | Транзакции, частичные уникальные индексы и exclusion-ограничения закрывают BR-05…BR-08 на уровне БД (NFR-04) |

## 12.3. Ключевые архитектурные решения

| ID | Решение | Альтернатива | Почему выбрано | Требования |
|---|---|---|---|---|
| ADR-01 | Атомарное занятие места одним условным `UPDATE … WHERE booked_count < capacity` в транзакции вместе с созданием записи | Распределённая блокировка, очередь запросов на сеанс | Просто, надёжно, выдерживает конкуренцию без дополнительной инфраструктуры | FR-10, NFR-03 |
| ADR-02 | Ограничения целостности дублируются в БД: частичный уникальный индекс «одна активная запись клиента на сеанс», exclusion-ограничение на пересечение активных записей клиента, `CHECK (booked_count BETWEEN 0 AND capacity)` | Проверки только в коде | Защищает от гонок и ошибок в коде, даже если проверка в приложении пропущена | FR-11, FR-12, NFR-04 |
| ADR-03 | Уведомления записываются в таблицу `notification` в той же транзакции, что и изменение записи. Worker отправляет их позже (паттерн Transactional Outbox) | Отправка push прямо из запроса, брокер сообщений | Уведомление не теряется и не отправляется по откатившейся транзакции, а сбой push не ломает запись. Отдельный брокер для MVP избыточен | FR-15, FR-27, FR-28, NFR-07 |
| ADR-04 | Напоминание — это запись в `notification` с будущим временем отправки (`send_at`). При отмене записи оно помечается отменённым | Отдельный планировщик задач | Одна модель и один обработчик для всех уведомлений | FR-20, FR-26 |
| ADR-05 | Операции клуба выполняются через служебный API (`/internal/v1`), а не прямым SQL | Прямые UPDATE в БД | Отмена сеанса и замена тренера запускают ту же логику уведомлений и истории, что и остальная система. Прямой SQL остаётся только для загрузки справочников | FR-22, FR-23, R-05 |
| ADR-06 | Бронь персонального слота сериализуется блокировкой строки тренера (`SELECT … FOR UPDATE`) на время проверки пересечений | Exclusion-ограничение на сеансы тренера | Персональные слоты тренера могут пересекаться между собой по замыслу (18:00 и 18:30), поэтому конфликт определяется только по занятым слотам в момент брони | FR-13 |
