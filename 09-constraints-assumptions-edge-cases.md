# 09. Ограничения, допущения, риски и краевые кейсы

## 9.1. Ограничения

Ограничение (`C`) — условие, заданное извне, которое проект не может изменить.

| ID | Ограничение | Источник | Влияние на решение |
|---|---|---|---|
| C-01 | В MVP нет административной панели. Мастер-данные загружаются в БД техническими средствами | ТЗ | Изменения расписания выполняются как технические операции (FR-22…FR-24) |
| C-02 | Аутентификация и авторизация выполняются внешним сервисом, от него приходит только идентификатор пользователя | ТЗ | В MVP нет регистрации и профиля, клиент хранится как `user_id`. Собственная регистрация и вход — Этап 2 (OS-02) |
| C-03 | Длительность занятия фиксирована: 45, 60 или 90 минут | ТЗ | Длительность — атрибут вида занятия, конец сеанса вычисляется |
| C-04 | Вместимость персональной тренировки = 1 | ТЗ | Единая сущность «Сеанс» с типом и вместимостью |
| C-05 | Возврат места при отмене и занятие места при записи атомарны | ТЗ | FR-10, FR-18, NFR-03 |
| C-06 | Один клуб, один часовой пояс | Решение по объёму MVP | Нет сущности «Клуб», параметр `club_timezone` |
| C-07 | Канал для клиента — только мобильное приложение (iOS, Android) | Решение по объёму MVP | Push через APNs / FCM, веб-версии нет |

## 9.2. Допущения

Допущение (`A`) — принятое как истинное утверждение, которое не проверено. Если оно не подтвердится, требования придётся пересмотреть.

| ID | Допущение | Что будет, если неверно |
|---|---|---|
| A-01 | Любой авторизованный пользователь — держатель действующей клубной карты. С картой доступны все групповые занятия, тарифов нет | Нужна интеграция с учётной системой клуба для проверки карты |
| A-02 | Токен внешнего сервиса позволяет получить стабильный `user_id`, одинаковый на всех устройствах клиента | Записи клиента «разъедутся» между устройствами |
| A-03 | Тех. специалист ежедневно поддерживает расписание минимум на 14 дней вперёд | В дальних днях расписание пустое, падает BG-01 |
| A-04 | Персональный тренер открывает для онлайн-записи только часы, свободные от прямых договорённостей, и сообщает о закрытии слота до того, как отдаёт время клиенту напрямую | Возможна накладка онлайн-брони и прямой договорённости (R-01, EC-25) |
| A-05 | Стоимость, оплата и программа персональной тренировки согласуются между клиентом и тренером напрямую, система их не хранит | Нужен модуль цен и оплаты |
| A-06 | Запись на групповые занятия ведётся только через приложение, ресепшн не ведёт параллельный журнал. Приход без записи на свободное место допускается по решению тренера и системой не учитывается | Два источника записи вернут овербукинг |
| A-07 | Клиент может пользоваться приложением с нескольких устройств, push приходит на все | — |
| A-08 | Исходное состояние AS-IS и целевые значения метрик являются гипотезами и уточняются замером | Цели BG-01…BG-03 пересматриваются |
| A-09 | Данные о посещениях для расчёта BG-01 клуб получает из системы турникетов, вне нашей системы | Метрику BG-01 придётся считать иначе |

## 9.3. Риски

| ID | Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|---|
| R-01 | Тренер договорился с клиентом напрямую на время, уже открытое онлайн, и слот одновременно бронирует другой клиент | Средняя | Среднее | Регламент A-04. Если накладка произошла, тренер согласует с клиентом, а онлайн-запись отменяется клубом (FR-22). В Этапе 2 — интерфейс тренера с закрытием слотов |
| R-02 | Расписание не загружено вовремя | Средняя | Высокое | Регламент загрузки, алерт «на дату D+13 нет сеансов» |
| R-03 | Клиенты не переходят в приложение | Средняя | Высокое | Ресепшн помогает установить приложение, QR на стойке и в залах |
| R-04 | Клиент отключил push и пропускает изменения | Высокая | Низкое | Лента уведомлений в приложении, счётчик непрочитанных |
| R-05 | Ошибка при технической операции (например, отменён не тот сеанс) | Низкая | Высокое | Операции только по заявке, журнал аудита (NFR-14), проверочные ограничения FR-24 |

## 9.4. Краевые кейсы

Краевой кейс (`EC`) — нетипичная ситуация, для которой явно определено поведение системы.

### Запись и конкуренция

| ID | Ситуация | Ожидаемое поведение | FR |
|---|---|---|---|
| EC-01 | Два клиента одновременно записываются на последнее место | Ровно один получает запись, второй — `SESSION_FULL` | FR-10 |
| EC-02 | Двойное нажатие «Записаться» или повтор запроса из-за сбоя сети | Создаётся одна запись, повтор возвращает её же | FR-14 |
| EC-03 | Клиент уже записан с другого устройства и пытается записаться снова | `ALREADY_BOOKED`, в приложении — ссылка на существующую запись | FR-09 |
| EC-04 | На заполненный сеанс одновременно приходят отмена клиента A и запись клиента B | Счётчик корректен. B получает место, если отмена зафиксирована раньше, иначе — `SESSION_FULL` | FR-10, FR-18 |
| EC-05 | Клиент видит «Осталось 1», но место заняли, пока он открывал карточку | Отказ `SESSION_FULL`, экран обновляет число мест | FR-10 |
| EC-06 | Попытка записаться на сеанс за пределами 14 дней (напрямую через API) | `OUT_OF_HORIZON` | FR-09 |
| EC-07 | Попытка записаться на уже начавшееся групповое занятие | `BOOKING_CLOSED` | FR-09 |
| EC-08 | Попытка забронировать персональный слот менее чем за 24 часа | Слот не показывается. Через API — `BOOKING_CLOSED` | FR-06, FR-09 |
| EC-09 | Сеанс отменён клубом, пока клиент смотрел карточку | `SESSION_CANCELLED` | FR-09 |

### Пересечения по времени

| ID | Ситуация | Ожидаемое поведение | FR |
|---|---|---|---|
| EC-10 | У клиента запись 18:00–19:00, он записывается на 19:00–20:00 | Разрешено: интервалы не пересекаются | FR-12 |
| EC-11 | У клиента йога 19:00–20:00, он бронирует персональную 19:30–20:30 | `CLIENT_TIME_CONFLICT` с указанием записи на йогу | FR-09, FR-12 |
| EC-12 | У тренера слоты 18:00–19:00 и 18:30–19:30, первый забронирован | Второй слот исчезает из расписания. Через API — `TRAINER_BUSY` | FR-06, FR-13 |
| EC-13 | Персональный слот пересекается с групповым сеансом того же тренера (ошибка загрузки данных) | Слот не показывается, бронь отклоняется `TRAINER_BUSY` | FR-13 |

### Отмена

| ID | Ситуация | Ожидаемое поведение | FR |
|---|---|---|---|
| EC-14 | Отмена группового в 19:00 ровно в 18:30:00 | Разрешено (граница включительно) | FR-16 |
| EC-15 | Клиент открыл карточку в 18:29, нажал «Отменить» в 18:31 | `CANCELLATION_DEADLINE_PASSED`. Решает серверное время, кнопка на экране становится неактивной | FR-16 |
| EC-16 | Повторная отмена уже отменённой записи | Возвращается текущее состояние, счётчик не меняется | FR-19 |
| EC-17 | Попытка отменить завершённую или отменённую клубом запись | `BOOKING_NOT_ACTIVE` | FR-19 |
| EC-18 | Попытка отменить чужую запись | `404`, существование записи не раскрывается | FR-03 |
| EC-19 | Клиент отменил запись и хочет записаться снова | Разрешено, если окно записи открыто и есть места. Создаётся новая запись | FR-21 |

### Изменения со стороны клуба

| ID | Ситуация | Ожидаемое поведение | FR |
|---|---|---|---|
| EC-20 | Сеанс отменяется, часть записей уже отменена клиентами | Меняются только записи `ACTIVE`, остальные сохраняют статус | FR-22 |
| EC-21 | Замена тренера группового занятия после дедлайна отмены | Клиенты могут отменить запись до начала сеанса | FR-17, FR-23 |
| EC-22 | Повторная замена тренера на том же сеансе | Признак свободной отмены сохраняется, клиенты получают новое уведомление | FR-23 |
| EC-23 | Персональный тренер заболел | Слот отменяется (FR-22), замена не предлагается | FR-22, FR-23 |
| EC-24 | Попытка уменьшить вместимость ниже числа записей или перенести время сеанса с записями | Операция отклоняется, перенос делается через отмену и новый сеанс | FR-24 |
| EC-25 | Тренер договорился напрямую на время, которое уже забронировал другой клиент онлайн | Онлайн-бронь действительна. Тренер решает накладку с клиентами. Если онлайн-бронь снимается — это отмена клубом с уведомлением | FR-22, A-04 |
| EC-26 | Тренер уволился, у него есть будущие сеансы | Тех. специалист отменяет его групповые сеансы или меняет тренера, а персональные слоты отменяет | FR-22, FR-23 |

### Уведомления, доступ и сбои

| ID | Ситуация | Ожидаемое поведение | FR |
|---|---|---|---|
| EC-27 | Клиент записался менее чем за 2 часа до начала | Напоминание не планируется | FR-26 |
| EC-28 | Push отключён пользователем или не доставлен | Уведомление есть в ленте, запись действительна | FR-27, FR-28 |
| EC-29 | Токен доступа просрочен | `401`, приложение обновляет токен через сервис аутентификации и повторяет запрос | FR-01 |
| EC-30 | Сервис аутентификации недоступен | `503`, приложение показывает сообщение о техническом сбое. Данные не меняются | FR-01 |
| EC-31 | Клиент превысил лимит запросов на запись | `429`, приложение предлагает повторить позже | NFR-12 |
