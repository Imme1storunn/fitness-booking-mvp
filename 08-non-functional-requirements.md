# 08. Нефункциональные требования

Нефункциональные требования (`NFR`) задают **качество** работы системы. Числовые значения рассчитаны из профиля нагрузки (8.1) и являются допущениями MVP, которые подтверждаются нагрузочным тестом до запуска.

## 8.1. Профиль нагрузки (исходные данные)

| Параметр | Значение | Обоснование |
|---|---|---|
| Держатели клубных карт | ~5 000 | Средний клуб сетевого формата |
| Активные пользователи приложения в день | ~1 500 | 30 % базы, цель BG-01 |
| Групповых сеансов в день | ~40 | 4 зала × ~10 слотов с 07:00 до 22:00 |
| Персональных слотов в день | ~150 | ~15 тренеров × ~10 слотов |
| Пиковые часы | 07:00–09:00 и 18:00–21:00 | Утренний и вечерний пик посещений |
| Пиковая нагрузка на чтение | до 50 запросов/с | Просмотр расписания и карточек |
| Пиковая нагрузка на запись | до 10 запросов/с | Запись и отмена |
| Конкуренция за один сеанс | до 500 одновременных попыток | Популярное занятие с 25 местами |

## 8.2. Требования

| ID | Категория | Требование | Значение / метрика | Как проверяем | BR |
|---|---|---|---|---|---|
| NFR-01 | Производительность | Время ответа на получение расписания дня | p95 ≤ 500 мс при 50 запросах/с | Нагрузочный тест | BR-01 |
| NFR-02 | Производительность | Время ответа на создание и отмену записи | p95 ≤ 1 с при 10 запросах/с | Нагрузочный тест | BR-03, BR-09 |
| NFR-03 | Консистентность | Число активных записей на сеанс никогда не превышает вместимость, `booked_count` всегда равен числу активных записей | 0 расхождений | Тест 500 параллельных запросов + ежечасная сверочная проверка с алертом | BR-05, BR-10 |
| NFR-04 | Консистентность | Ограничения «одна активная запись клиента на сеанс» и «место не больше вместимости» закреплены на уровне БД, а не только в коде | Есть уникальный индекс и проверочное условие | Ревью схемы БД | BR-05, BR-06 |
| NFR-05 | Доступность | Доступность API записи | ≥ 99,5 % в месяц (простой ≤ 3,6 ч) | Мониторинг доступности | BR-17 |
| NFR-06 | Надёжность | Точка восстановления и время восстановления после сбоя | RPO ≤ 15 мин, RTO ≤ 1 ч | Учения по восстановлению из резервной копии | BR-17 |
| NFR-07 | Надёжность | Недоступность APNs / FCM не влияет на запись и отмену | Запись успешна при недоступном push-сервисе | Тест с отключённым push-сервисом | BR-15 |
| NFR-08 | Своевременность | Уведомление о событии формируется быстро, напоминание приходит вовремя | Событие → лента ≤ 10 с; напоминание ±5 мин | Интеграционный тест, мониторинг очереди | BR-15, BR-16 |
| NFR-09 | Своевременность | Освобождённое место видно другим клиентам | Сразу после ответа на отмену (без кэша на счётчике мест) | Функциональный тест | BR-10 |
| NFR-10 | Безопасность | Все обращения к API идут по HTTPS | TLS 1.2+ | Сканирование конфигурации | — |
| NFR-11 | Безопасность | Клиент имеет доступ только к своим данным | 0 уязвимостей класса IDOR | Тест безопасности | — |
| NFR-12 | Безопасность | Ограничение частоты запросов на запись и отмену от одного пользователя | ≤ 30 запросов/мин, сверх лимита — `429` | Функциональный тест | BR-05 |
| NFR-13 | Приватность | Хранение только `user_id` и токенов устройств, без персональных данных | Соответствует FR-02 | Ревью модели данных | — |
| NFR-14 | Аудит | Все изменения статусов записей и технические операции клуба журналируются с инициатором и временем | 100 % операций | Проверка журнала | BR-18 |
| NFR-15 | Хранение данных | Записи и история статусов хранятся для аналитики | ≥ 2 года | Политика хранения | BR-18 |
| NFR-16 | Время | Все даты хранятся в UTC, отображаются в часовом поясе клуба | Часовой пояс — параметр `club_timezone` | Тест на границе суток | BR-01 |
| NFR-17 | Совместимость | Поддерживаемые версии мобильных ОС | iOS 16+, Android 9+ | Тест на матрице устройств | BR-01 |
| NFR-18 | Удобство | Запись с экрана расписания | ≤ 3 нажатий: занятие → «Записаться» → подтверждение | Юзабилити-тест | BG-01 |
| NFR-19 | Удобство | Сообщения об отказах понятны пользователю | Тексты по таблице [6.5](06-user-requirements.md#65-сообщения-пользователю), на русском | Ревью UI | BR-05…BR-09 |
| NFR-20 | Наблюдаемость | Метрики: количество записей и отмен, отказы по причинам, время ответа, очередь уведомлений | Дашборд и алерты на рост ошибок | Проверка мониторинга | BR-18 |
| NFR-21 | Сопровождаемость | Правила записи меняются через настройки без релиза | См. FR-30 | Функциональный тест | BR-11 |
| NFR-22 | Масштабируемость | Сервис API без состояния, масштабируется горизонтально. Модель данных допускает добавление клуба как измерения | Добавление экземпляров без изменения кода | Архитектурное ревью | BR-19 |
