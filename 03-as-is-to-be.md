# 03. Процессы AS-IS и TO-BE


## 3.1. AS-IS: запись на занятие через ресепшн

**Участники:** клиент, администратор ресепшн, журнал записи (бумажный или таблица).

1. Клиент звонит на ресепшн или подходит лично. Это возможно только в часы работы ресепшн, 10:00–22:00.
2. Администратор находит сеанс в журнале и пересчитывает записавшихся вручную.
3. Если мест нет, клиенту отказывают, иногда он записывается «в резерв» на словах.
4. Если места есть, администратор вписывает клиента в журнал.
5. Отмена происходит так же, через звонок. Если клиент не позвонил, место остаётся занятым до начала занятия.

![AS-IS: запись через ресепшн](img/as-is-booking.svg)

### Проблемы AS-IS

| # | Где в процессе | Проблема | Связь с целью |
|---|---|---|---|
| AS-1 | Шаг 1 | Запись ограничена часами ресепшн и дозвоном | BG-01, BG-03 |
| AS-2 | Шаг 2–3 | Клиент не видит свободные места до звонка | BG-01, BG-02 |
| AS-3 | Шаг 3–4 | Параллельная запись двумя администраторами ведёт к овербукингу | BG-04 |
| AS-4 | Шаг 5 | Неотменённые записи дают пустые места на занятии | BG-03 |
| AS-5 | Весь процесс | Все операции проходят через администратора | BG-02 |

## 3.2. TO-BE: запись через мобильное приложение

**Участники:** клиент, мобильное приложение, система записи (backend), сервис аутентификации (внешний), сервис push-уведомлений платформы (APNs / FCM).

1. Клиент открывает приложение. Сервис аутентификации подтверждает его личность и передаёт идентификатор пользователя.
2. Клиент видит расписание на выбранный день (до 14 дней вперёд) с числом свободных мест и фильтрует по виду, тренеру и уровню.
3. Клиент выбирает сеанс и нажимает «Записаться».
4. Система в одной атомарной операции проверяет:
   - окно записи не закрыто;
   - есть свободное место;
   - клиент ещё не записан на этот сеанс;
   - у клиента нет пересекающейся записи;
   - для персональной тренировки у тренера нет пересекающегося занятия.
5. При успехе место занимается, запись получает статус «Активна», клиенту приходит push и запись появляется в «Моих записях».
6. При отказе клиент видит понятную причину («Мест нет», «Вы уже записаны», «Пересечение с записью на 19:00»).
7. За 2 часа до начала клиент получает напоминание.

![TO-BE: запись через приложение](img/to-be-booking.svg)

## 3.3. TO-BE: отмена записи клиентом

1. В «Моих записях» клиент нажимает «Отменить» у предстоящей записи. Кнопка активна до дедлайна: за 30 минут до начала для группового занятия и за 24 часа для персонального.
2. Система повторно проверяет дедлайн на сервере, переводит запись в статус «Отменена клиентом» и атомарно возвращает место.
3. Освобождённое место сразу видно другим клиентам в расписании.
4. Клиент получает push с подтверждением отмены.

![TO-BE: отмена записи клиентом](img/to-be-cancel.svg)

## 3.4. TO-BE: изменение занятия со стороны клуба

Админ-панели в MVP нет, поэтому изменение вносит технический специалист (SH-11) по заявке управляющего. После изменения система сама обрабатывает затронутые записи.

- **Отмена сеанса** возможна для любого типа занятия. Все активные записи переходят в «Отменена клубом», клиенты получают уведомление.
- **Замена тренера** возможна только для группового занятия. Персональная тренировка привязана к конкретному тренеру: если он не может её провести (например, заболел), тренировка отменяется, замена не предлагается.

![TO-BE: изменение занятия со стороны клуба](img/to-be-club-change.svg)

## 3.5. Что меняется: AS-IS → TO-BE

| Аспект | AS-IS | TO-BE | Цель |
|---|---|---|---|
| Канал записи | Звонок / визит на ресепшн | Мобильное приложение, 24/7 | BG-01 |
| Видимость мест | Только после звонка | «Осталось 7/25» в расписании | BG-01, BG-02 |
| Отмена | Звонок, часто её нет вовсе | Кнопка в приложении, место возвращается сразу | BG-02, BG-03 |
| Контроль лимита | Ручной пересчёт | Атомарная проверка на сервере | BG-04 |
| Изменения от клуба | Обзвон клиентов администратором | Автоматическая смена статуса + push | BG-02 |
| Напоминание | Нет | Push за 2 часа до начала | BG-03 |
