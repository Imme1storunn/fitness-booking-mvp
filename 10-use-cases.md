# 10. Варианты использования (Use Cases)

Вариант использования (`UC`) описывает **взаимодействие актора с системой** от триггера до результата, включая альтернативные ветки и исключения. Юзкейсы связывают пользовательские требования ([06](06-user-requirements.md)) и функциональные ([07](07-functional-requirements.md)) в сквозные сценарии. Эти же сценарии затем раскладываются на юзер-стори ([11](11-user-stories.md)) и сиквенс-диаграммы ([15](15-sequence-diagrams.md)).

## 10.1. Акторы

| Актор | Тип | Описание |
|---|---|---|
| Клиент | Основной | Держатель клубной карты, работает через мобильное приложение |
| Тех. специалист | Основной | Выполняет технические операции по заявке управляющего |
| Таймер | Основной (системный) | Планировщик задач системы, запускает действия по времени |
| Сервис аутентификации | Второстепенный | Внешний. Проверяет токен и выдаёт `user_id` |
| APNs / FCM | Второстепенный | Платформенные сервисы доставки push |

## 10.4. Краткие описания

| ID | Триггер | Основной сценарий | Результат |
|---|---|---|---|
| UC-01 | Клиент открывает приложение или вкладку «Расписание» | Система возвращает сеансы на сегодня. Клиент переключает день (до 14 дней вперёд) и применяет фильтры. Система возвращает отфильтрованный список со свободными местами и состоянием записи. Недоступные персональные слоты скрыты | Клиент видит актуальное расписание |
| UC-02 | Клиент выбирает занятие в расписании | Система возвращает карточку с описанием, тренером, залом, уровнем, местами и состоянием кнопки «Записаться». Для персонального — пометка про оплату напрямую | Клиент видит детали и может перейти к UC-03 / UC-04 |
| UC-05 | Клиент открывает «Мои записи» | Система возвращает только записи клиента: предстоящие (`ACTIVE`) с дедлайном отмены и историю (прочие статусы) | Клиент видит свои записи |
| UC-07 | Клиент открывает ленту или нажимает на push | Система возвращает уведомления клиента, счётчик непрочитанных. При открытии уведомление отмечается прочитанным, клиент может перейти к записи | Клиент прочитал уведомление |
| UC-10 | Таймер, раз в 5 минут | Система находит активные записи на сеансы с `end ≤ now` и переводит их в `COMPLETED` с инициатором `SYSTEM` | Прошедшие записи завершены |
| UC-11 | Таймер, наступило время напоминания | Система проверяет, что запись ещё `ACTIVE`, создаёт уведомление `REMINDER` и отправляет push. При сбое повторяет до 3 раз | Клиент получил напоминание |

## 10.5. UC-03. Записаться на групповое занятие

| Поле | Значение |
|---|---|
| Основной актор | Клиент |
| Второстепенные акторы | Сервис аутентификации, APNs / FCM |
| Предусловия | Клиент аутентифицирован. Сеанс опубликован в расписании |
| Триггер | Клиент нажимает «Записаться» в карточке группового занятия |
| Гарантии успеха | Создана запись `ACTIVE`, `booked_count` увеличен на 1, создано уведомление, запланировано напоминание |
| Минимальные гарантии | При любом отказе запись не создана, `booked_count` не изменился |

**Основной сценарий**

1. Клиент открывает карточку группового занятия (UC-02) и нажимает «Записаться».
2. Приложение отправляет запрос на создание записи с ключом идемпотентности.
3. Система проверяет токен через сервис аутентификации и получает `user_id`.
4. Система проверяет правила записи: сеанс существует и не отменён, в пределах горизонта, запись открыта, клиент не записан на этот сеанс, нет пересечений с его записями (FR-09, шаги 1–6).
5. Система атомарно занимает место и создаёт запись в статусе `ACTIVE`.
6. Система создаёт уведомление «Запись подтверждена», ставит push в очередь и планирует напоминание.
7. Система возвращает созданную запись.
8. Приложение показывает экран результата с дедлайном отмены: «Отменить можно до 18:30».

**Альтернативные сценарии и исключения**

| Шаг | Условие | Поведение | EC |
|---|---|---|---|
| 1a | Кнопка неактивна: мест нет, запись закрыта или клиент уже записан | На кнопке показана причина, сценарий завершается | — |
| 2a | Повтор запроса с тем же ключом (двойное нажатие, сбой сети) | Система возвращает результат первого запроса, новая запись не создаётся | EC-02 |
| 3a | Токен просрочен | `401`. Приложение обновляет токен и повторяет запрос с тем же ключом | EC-29 |
| 3b | Сервис аутентификации недоступен | `503`, сообщение о техническом сбое | EC-30 |
| 4a | Сеанс отменён клубом | `SESSION_CANCELLED`, приложение обновляет карточку | EC-09 |
| 4b | Занятие уже началось или вне горизонта | `BOOKING_CLOSED` / `OUT_OF_HORIZON` | EC-06, EC-07 |
| 4c | Клиент уже записан (например, с другого устройства) | `ALREADY_BOOKED`, приложение предлагает перейти к записи | EC-03 |
| 4d | Есть пересекающаяся запись клиента | `CLIENT_TIME_CONFLICT` с указанием конфликтующей записи | EC-11 |
| 5a | Свободных мест не осталось, в том числе если последнее место занято параллельно | `SESSION_FULL`, приложение обновляет число мест | EC-01, EC-05 |
| 6a | Push не доставлен | Уведомление остаётся в ленте, запись действительна | EC-28 |
| 6b | До начала меньше 2 часов | Напоминание не планируется | EC-27 |

## 10.6. UC-04. Забронировать персональную тренировку

| Поле | Значение |
|---|---|
| Основной актор | Клиент |
| Второстепенные акторы | Сервис аутентификации, APNs / FCM |
| Предусловия | Клиент аутентифицирован. Тренер открыл слот для онлайн-записи, и тех. специалист его опубликовал |
| Триггер | Клиент нажимает «Записаться» в карточке персонального слота |
| Гарантии успеха | Создана запись `ACTIVE` на слот, слот и пересекающиеся слоты тренера скрыты из расписания |
| Минимальные гарантии | При отказе запись не создана |

**Основной сценарий**

1. Клиент фильтрует расписание по типу «Персональные» и, при желании, по тренеру (UC-01).
2. Клиент открывает карточку слота. Система показывает тренера, время и пометку «Стоимость и оплата — по договорённости с тренером».
3. Клиент нажимает «Записаться».
4. Шаги 2–4 UC-03. Дополнительно система проверяет, что до начала не меньше 24 часов, а у тренера нет пересекающегося занятия (FR-13).
5. Система атомарно занимает слот (вместимость 1) и создаёт запись `ACTIVE`.
6. Шаги 6–8 UC-03.
7. Клиент при необходимости связывается с тренером напрямую, чтобы согласовать оплату и программу. Это происходит вне системы.

**Альтернативные сценарии и исключения**

Все исключения UC-03, а также:

| Шаг | Условие | Поведение | EC |
|---|---|---|---|
| 4a | До начала меньше 24 часов | `BOOKING_CLOSED`. В расписании такой слот уже не показывается | EC-08 |
| 4b | У тренера пересекающееся занятие: забронирован соседний слот или есть групповой сеанс | `TRAINER_BUSY` | EC-12, EC-13 |
| 5a | Слот одновременно бронирует другой клиент | Один успех, второй получает `SESSION_FULL` | EC-01 |

## 10.7. UC-06. Отменить запись

| Поле | Значение |
|---|---|
| Основной актор | Клиент |
| Второстепенные акторы | Сервис аутентификации, APNs / FCM |
| Предусловия | У клиента есть запись в статусе `ACTIVE` |
| Триггер | Клиент нажимает «Отменить» в карточке записи |
| Гарантии успеха | Запись в статусе `CANCELLED_BY_CLIENT`, `booked_count` уменьшен на 1, напоминание отменено, место доступно другим |
| Минимальные гарантии | При отказе запись и счётчик не изменились |

**Основной сценарий**

1. Клиент открывает «Мои записи» (UC-05) и выбирает предстоящую запись. Приложение показывает «Отменить можно до …».
2. Клиент нажимает «Отменить» и подтверждает действие.
3. Система проверяет токен и то, что запись принадлежит клиенту.
4. Система проверяет, что запись `ACTIVE` и текущее время не позже `start − дедлайн`: 30 минут для группового занятия, 24 часа для персонального.
5. Система атомарно переводит запись в `CANCELLED_BY_CLIENT` и уменьшает `booked_count` на 1.
6. Система отменяет напоминание, создаёт уведомление «Запись отменена» и ставит push в очередь.
7. Приложение показывает запись в истории со статусом «Отменена».

**Альтернативные сценарии и исключения**

| Шаг | Условие | Поведение | EC |
|---|---|---|---|
| 3a | Запись принадлежит другому клиенту | `404` | EC-18 |
| 4a | Дедлайн прошёл | `CANCELLATION_DEADLINE_PASSED`, кнопка становится неактивной | EC-15 |
| 4b | У записи признак свободной отмены (заменён тренер группового) | Дедлайн не применяется, отмена возможна до начала | EC-21 |
| 4c | Запись уже отменена клиентом | Возвращается текущее состояние, изменений нет | EC-16 |
| 4d | Запись завершена или отменена клубом | `BOOKING_NOT_ACTIVE` | EC-17 |
| 5a | Одновременно идёт запись другого клиента на этот сеанс | Счётчик остаётся корректным при любом порядке операций | EC-04 |

## 10.8. UC-08. Отменить сеанс

| Поле | Значение |
|---|---|
| Основной актор | Тех. специалист |
| Второстепенные акторы | APNs / FCM |
| Предусловия | Есть заявка управляющего на отмену. Сеанс в статусе `SCHEDULED` |
| Триггер | Тех. специалист запускает операцию отмены сеанса |
| Гарантии успеха | Сеанс `CANCELLED`, все его активные записи `CANCELLED_BY_CLUB`, клиенты уведомлены |
| Минимальные гарантии | При ошибке транзакция откатывается целиком, частичной отмены нет |

**Основной сценарий**

1. Тех. специалист вызывает служебную операцию отмены сеанса с указанием причины.
2. Система в одной транзакции переводит сеанс в `CANCELLED`, все записи `ACTIVE` — в `CANCELLED_BY_CLUB` с инициатором `CLUB`, обнуляет `booked_count`.
3. Система отменяет запланированные напоминания и создаёт каждому затронутому клиенту уведомление «Занятие отменено клубом».
4. Система ставит push в очередь и возвращает число затронутых записей.
5. Сеанс перестаёт отображаться в расписании.

**Альтернативные сценарии и исключения**

| Шаг | Условие | Поведение | EC |
|---|---|---|---|
| 1a | Отменяется персональный слот, так как тренер не может провести тренировку | Сценарий тот же, замена не предлагается | EC-23 |
| 1b | Сеанс уже отменён или завершён | Операция отклоняется | — |
| 2a | Часть записей уже отменена клиентами | Меняются только `ACTIVE` | EC-20 |

## 10.9. UC-09. Заменить тренера группового занятия

| Поле | Значение |
|---|---|
| Основной актор | Тех. специалист |
| Второстепенные акторы | APNs / FCM |
| Предусловия | Есть заявка управляющего. Сеанс групповой, в статусе `SCHEDULED`, ещё не начался |
| Триггер | Тех. специалист запускает операцию замены тренера |
| Гарантии успеха | У сеанса новый тренер, активные записи сохранены с признаком свободной отмены, клиенты уведомлены |
| Минимальные гарантии | При ошибке изменений нет |

**Основной сценарий**

1. Тех. специалист вызывает операцию замены тренера с указанием нового тренера.
2. Система проверяет, что сеанс групповой и новый тренер свободен на интервале сеанса.
3. Система меняет тренера и ставит активным записям признак свободной отмены.
4. Система создаёт уведомления «Тренер заменён на {имя}. Вы можете отменить запись до начала занятия».
5. Карточка сеанса в расписании показывает нового тренера.

**Альтернативные сценарии и исключения**

| Шаг | Условие | Поведение | EC |
|---|---|---|---|
| 2a | Сеанс персональный | Операция отклоняется, нужно использовать UC-08 | EC-23 |
| 2b | Новый тренер занят в этот интервал | Операция отклоняется | — |
| 3a | Тренер на этом сеансе уже заменялся | Признак сохраняется, клиенты получают новое уведомление | EC-22 |
